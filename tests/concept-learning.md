# concept-learning 개발·검증 계획

작업 범위: 새 독립 스킬 `concept-learning`, 교수법·기술별 기준·자료/이미지·주제 맥락·품질 사례·프로젝트 연결 참고 문서, Skills-only 플러그인 및 기존 개인 마켓플레이스/CI/README 연계. 기존 다섯 스킬·원본 학습 프로젝트·Wiki·Obsidian은 변경하지 않는다.

## 근거와 요구사항

- 사용자와 확정한 개념 학습 방식: 한국어 `~이다`체 강사형 설명, 연결된 문단, 중요도에 따른 깊이, 코드 이후 실행·상태 해설, 한국어 기술 자료와 공식 명세, 이미지 선택적 활용, 후속 질문 집중.
- 학습 진도는 별도 프로젝트·PDF를 사용하며, 퀴즈·실습·노트/블로그 게시·외부 저장은 요청 없는 기본 동작으로 추가하지 않는다.
- 기존 `cs-learning-visualization`과 역할을 분리하고 필수 종속성으로 연결하지 않는다.

## 최종 실행 명세 — 주제별 교수법 중심 (2026-11-09)

기존 PR 초안의 '로드맵 진행자' 설계는 **사용자 피드백으로 폐기**했다. 실제 목적은 새 채팅마다 교수법과 글 구성 규칙을 재지정하지 않도록 만드는 것이다.

- **로드맵 주제:** 사용자가 이미 정한 Java 학습 맥락에서 `$concept-learning 다형성1부터 진행하자`라고 하면 다형성1을 강의한다. 스킬은 로드맵을 생성하거나 진도를 조회·변경하지 않는다.
- **독립 주제:** `$concept-learning Spring의 Bean 생명주기 설명해줘`에도 같은 교수법을 적용한다. 로드맵 확인을 요구하지 않는다.
- **설명 기준:** Java/Spring 백엔드 개발자 취업 준비생의 눈높이, `~이다`체와 **한 줄 문장/문단 반복 지양**, 코드 뒤 실행 설명, 중요도에 따른 심화, 소제목 절제, 후속 질문 중심.
- **한글 자료:** 공식 명세로 정확성을 확인하고 국내 IT 기업·검증된 한국어 기술 글을 적극 조사한다. 확인한 내용의 맥락을 본문에 반영하고 해당 문단 곁에 출처 링크를 제공한다.
- **그림:** 개념에 도움이 되면 강의 공개 이미지·기술 구조도를 적극 탐색하고 출처·실제 그림·이용 조건을 확인한다. 필요시에만 독립 도식/표를 활용한다.
- **미검증:** 정적 테스트는 실제 웹 출처 조사·이미지 표시·모델 교수 품질·새 채팅 자동 적용을 보장하지 않는다.

## 검증 단계와 상태

1. **정적 검사:** 원본 및 패키징된 스킬의 Agent Skills 형식, 참고 파일 포함/일치, 개인 마켓플레이스 여섯 항목, Markdown 구조·링크, 명시적 보안·기록 경계를 검사한다. 실행 결과는 CI와 독립적으로 기록한다.
2. **모델 응답 평가:** 실제 Codex/ChatGPT 모델에 최소 Java·Spring·JPA·Linux·악성 지시 사례를 요청하고 본문의 기술 정확성·반복·깊이·문체를 직접 평가한다. 코드가 실행되지 않았다면 추정 결과라고 말한다.
3. **클라이언트 검증:** 설치 후 Codex App/ChatGPT 데스크톱의 플러그인 목록 및 새 채팅 명시적 호출을 확인한다. GitHub CI 통과가 사용자 계정 설치를 증명하지 않는다.

**최초 작성 시점:** 이 문서는 테스트 계획이다. `CI 성공`, `모델 평가 통과`, `데스크톱 설치 완료` 등은 실제 실행 결과를 얻은 후에만 갱신한다. 보안 정적 검사가 자연어 프롬프트 주입 전체를 막는다고 보장하지 않는다.

정적 회귀 검사는 소스 규칙·패키지 복제·제외 목록과 시각화 우선순위 명시 여부를 확인한다. **실제 한국어 개발 글을 검색·열람했는지, 실제 이미지가 렌더링되는지, 모델의 강의 품질이 개선됐는지는 별도 실사용 평가가 필요하다.**

이 기록은 이전 성공 CI 결과를 수정 후의 결과로 오인하지 않는다. 새로운 PR의 CI 상태는 해당 PR 검증 결과를 기준으로 판단한다.

## 신입~2년 차 설명 품질 및 자체 QA 강화 (2026-11-10)

- 학습자 기준을 '기초 문법을 처음 배우는 입문자'에서 **신입~2년 차 Java/Spring 백엔드 실무 수준**으로 조정한다. 필요한 전제는 설명하되 반복된 기초 정의보다 코드/설계/트레이드오프를 우선한다.
- 장문 강의에서는 **주요 소제목·핵심 하위 주제마다 직접 관련된 기술 블로그**를 실제 검색·열람하고, 설명 인근에 링크와 원문의 핵심 내용을 배치한다. 개인 블로그·**테코블(Tecoble)**·기업 기술 블로그를 고루 탐색한다. 실제 확인되지 않은 링크/이미지는 제공하지 않는다.
- 시각적으로 설명할 가치가 있을 때 실제 내용 이미지를 우선 탐색한다. 파비콘·사이트 로고·빈 이미지 레이블·도식 설명 문장만 있는 경우 **시각 자료 검증 실패**로 본다.
- `references/response-quality-gate.md`의 8개 항목을 **답변 초안 이후 자체 검토**하고 REVISE 시 본문을 수정한다. 접근 불가한 출처/이미지는 LIMITATION으로 구분한다.
- GitHub Actions 정적 검사는 **규칙과 품질 게이트 문서 포함/패키징 일치/보안 계약**만 검증한다. 실제 생성 모델의 자연어 자체 감사 여부, 출처 링크 유효성, 이미지 표시와 학습자 수준은 **후속 사용성 시험에서만 확인 가능**하다. 자동 런타임 후크는 추가하지 않는다.
