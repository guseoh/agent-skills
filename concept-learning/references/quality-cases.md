# 개념 학습 응답 품질 사례 및 평가 계약

이 문서는 예시를 무조건 출력하는 템플릿이 아니라 **요청에 맞게 설명했는지 비교하는 검증 계약**이다. 아래 샘플 코드와 설명은 실행·운영 관찰 결과가 아닌 학습용 정적 예시다.

## 0. 사용자 지정 주제 강의 — 기본 동작

- **기존 로드맵 안의 주제:** `$concept-learning 다형성1부터 진행하자` → 기존 Java 학습 대화가 정해 둔 **다형성1**을 현재 학습 범위에 맞춰 바로 강의한다. 새 로드맵 작성, 진도 위치 조회·변경, 학습 목차 메뉴 제시로 답변을 대신하지 않는다.
- **독립 질문:** `$concept-learning Spring의 Bean 생명주기 설명해줘` → 로드맵을 요구하지 않고 Bean 생성·초기화·사용·소멸의 실제 동작과 조건을 설명한다. 위 두 경우에 같은 교수법·자료 조사·문단 규칙을 적용한다.
- **후속 질문:** `초기화 콜백이 정확히 언제 호출돼?` → 직전 강의를 처음부터 반복하지 않고 호출 시점과 관찰할 상태만 심화한다.
- **주제가 생략된 요청:** `다음 주제 진행하자`에 현재 대화에서 지칭하는 주제가 명확하지 않으면 새로운 로드맵을 구성하지 않고 **현재 주제 한 가지**만 확인한다.
- **절대 금지:** 스킬을 학습 진도 관리자로 간주하거나, 이전 PDF·로드맵을 실제로 열지 않고 확인했다고 단정하거나, `진행하자`와 `설명해줘`에 서로 다른 문체/품질 규칙을 적용하지 않는다.

## 0-1. 강사형 글 구성·한국어 출처·시각 자료

요청: `$concept-learning Spring Bean 생명주기를 기존 개념 학습 방식으로 설명해줘.`

- **합격 — 학습자 수준:** **신입~2년 차 Java/Spring 백엔드 개발자 수준**을 기준으로 Bean의 생성·의존성 주입·초기화·소멸 콜백의 흐름과 전제(Bean scope, 종료 컨텍스트 등)를 인과관계로 설명한다. 중요한 호출 조건은 짧은 실제 코드와 코드 뒤 동작 해설로 연결한다.
- **합격 — 문단:** `~이다`체의 자연스러운 **연결된 설명 문단**으로 원인과 결과를 설명한다. 필요한 부분만 소제목을 만들고 코드 구성·비교는 적절히 글머리표/표를 쓴다.
- **불합격 — 문단:** `Bean은 객체이다.` / `생명주기가 있다.` / `초기화가 호출된다.`처럼 **한 줄 문장/한 줄 문단만 연속으로 배치**하거나, 비슷한 소제목을 늘려 내용이 반복된다.
- **합격 — 한글 출처:** 기술적 사실은 실제 확인한 공식 문서로 검증하고, **관련성이 있는 국내 IT 기업 블로그 또는 검증된 한국어 기술 글을 적극 조사**한다. 실제로 읽은 글의 핵심과 적용 조건을 현재 소제목의 본문에 설명하고 링크를 근처에 둔다.
- **불합격 — 자료:** 확인하지 않은 회사 기술 글을 출처로 창작하거나, 소제목별 관련 자료를 찾아보지 않고 서론·결론에만 URL을 나열한다. 테코블·일반 개발 기술 블로그를 탐색하지 않고 공식 문서와 한 기업의 글만 반복하는 답변도 부족하다.
- **합격 — 이미지:** Bean 생명주기의 상태/콜백이 시각적으로 이해하기 유익하면 **실제 공개 강의 이미지·기술 구조도**를 찾아 이용 조건·출처·내용을 확인하고 본문에 활용한다. 적절한 이미지가 없으면 핵심 상태가 정확한 자체 도식·표를 사용하거나 그림 없이 충분히 설명한다.
- **불합격 — 이미지:** 강의 이미지가 실제로 없는 글을 원본 강의 그림으로 소개하거나, 파비콘·로고·빈 `[image]`를 관련 이미지로 표시하거나, 저작권 확인 없이 무단 복제, 무의미한 박스-화살표 그림 반복, 제공하지 못한 이미지를 제공했다고 주장.

## 0-2. 객체지향 강의에 대한 실제 실패 교정

사용자 요청: `$concept-learning 객체지향 프로그래밍과 객체지향 설계를 설명해줘.`

- **자료 실패:** 우아한형제들 글만 포함하고 개인 개발 블로그를 탐색하지 않은 채 한빛미디어·위키독스 같은 출판사/문서 플랫폼 페이지를 한국어 학습 자료로 추천하는 답변은 불합격이다. **Tistory·Velog·Medium·GitHub.io·hudi.blog 등 개인 개발 기술 글을 실제로 탐색**해 현재 주제에 적합한 자료를 엄선한다. 실재하지 않거나 내용을 확인하지 못한 글은 인용하지 않는다.
- **이미지 실패:** '객체지향 관점의 주문 처리'라는 텍스트만 표시하거나 빈 이미지 자리와 다수의 생성 도식으로 채우는 답변은 불합격이다. 시각적 도움이 필요하면 **기술 글/강의에 실제 포함된 관련 이미지**를 찾아 확인하고, 출처·이용 조건을 지켜 본문에 표시한다. 제공 불가능하면 빈 자리 대신 원본 링크·그림 해설 또는 꼭 필요한 보조 도식을 사용한다.
- **깊이 부족:** 객체·클래스·SOLID의 정의만 나열하고 끝내지 않는다. OOP와 OOD의 책임 경계, 좋은 설계를 판단하는 방법, 실제 Java 코드에서 상태 변경·협력이 수행되는 순서까지 설명한다. 이후 읽을 만한 **정보 전문가 원칙, Tell Don't Ask, 객체 불변식, 합성과 상속의 트레이드오프** 등 선택적 심화 키워드의 의의를 짚는다.
- **형식 실패:** 장문 설명을 강제하다 같은 내용을 반복하거나, 반대로 짧은 한 줄 문장만 줄줄이 쓰거나, 빈 표/깨진 Markdown 표를 방치하면 불합격이다. **깊은 설명은 문단, 역할·특성·비교·심화 키워드는 글머리표/표**로 구성한다.

## 0-3. 답변 직전 자체 검증 실패 사례

- **입문형 요약 실패:** '추상화는 핵심만 뽑는 것이다', '상속은 부모 기능을 물려받는다'라는 정의만 나열하고 **실제 변경 축·객체 간 계약·설계 트레이드오프·코드 실행 이유**를 설명하지 못한다.
- **소제목별 출처 실패:** 역할·책임·협력, 캡슐화, 다형성, 설계 품질에 대한 주요 단원이 있는데, 서론의 기업 블로그 1개와 결론의 공식 문서 1개만 연결하고 서로 다른 주제에 적합한 개인/테코블 글을 찾지 않는다.
- **파비콘을 이미지로 오인:** `https://www.google.com/s2/favicons?domain=...` 링크나 사이트 로고만 넣고 실제 원리 그림을 찾았다고 판단한다. 실제 이미지가 없는데 '실선은 요청, 점선은 반환' 같은 문장만 남겨 둔다.
- **중복 실패:** '객체지향은 클래스가 아니라 협력'이라는 결론을 서론·각 장·결론에서 반복하여 코드·책임 배분 설명보다 자리를 더 차지하게 한다.
- **수정 지침:** [답변 품질 게이트](response-quality-gate.md)에 대해 단계별로 **PASS / REVISE / LIMITATION**을 판정한다. REVISE라면 내용·출처·표현을 보완한 뒤 **다시 점검**한다. 자료·이미지 접근이 실제로 불가능한 LIMITATION만 정직하게 밝히며 성공으로 표시하지 않는다. 체크 결과를 사용자에게 매번 노출하지 않는다.

## 0-4. 조사 없이 먼저 작성한 다형성 강의 — 회귀 실패 사례

사용자 요청: `$concept-learning Java 다형성을 설계 원리와 참고 이미지까지 설명해줘.`

- **실패:** 먼저 `Dog/Cat` 반복 코드로 7개 장을 쓰고 나중에 검색된 테코블 링크 몇 개와 Google `s2/favicons`를 덧붙인다. 공개 기술 책의 연관 개념을 탐색하지 않고 '다형성 = 오버라이딩'에서만 설명 깊이를 결정한다.
- **수정:** [조사 우선 워크플로](research-first-workflow.md)에서 **다형적 참조·동적 디스패치 / 협력의 역할과 메시지 / 컴파일타임 vs 런타임 의존성 / 행동 계약과 LSP / 인터페이스 기반 선택**을 먼저 탐색한다. 《오브젝트》와 《객체지향의 사실과 오해》는 공개된 목차·저자 글·독서 해설을 찾기 위한 **탐색 키워드**로 사용하되, 읽지 않은 본문을 인용하지 않는다.
- **이미지 사전 확인:** 메서드 선택·참조 관계·인터페이스 구현을 설명하는 **실제 공개 기술 글의 내용 그림**을 별도 검색한다. 원본을 확인하고 표시 가능한 경우 본문에 실제 이미지를 넣는다. 파비콘·로고·텍스트 그림 캡션을 이미지로 간주하지 않으며 이용 조건에 따라 원본 링크만 제공할 수도 있다.
- **구조 결정:** 확인한 자료·이미지가 뒷받침하는 단원에 비중을 두고, 중복되는 입문 코드와 '실제 객체에 따라 메서드가 다르게 동작한다'는 문장 반복을 줄인다. 실제 출처 내용을 각 단원 근처에 제공하고 뒤늦게 만들어 낸 링크를 인용하지 않는다.
- **최종 확인:** 자체 게이트 `G0`(선조사)와 `G1~G8`을 **PASS / REVISE / LIMITATION**으로 검토한다. 자료·이미지 도구가 없다면 제한 사항을 사실대로 구분하고 기술 설명은 제공한다. **CI 계약 테스트는 실제 생성 품질을 증명하지 않는다.**

## 0-5. 책 관련성과 요청 동사별 응답 — 회귀 사례

- **상황 A — Java 다형성 설명:** `$concept-learning Java 다형성 설명해줘` → **EXPLAIN**에서 다형적 참조·동적 디스패치·설계와 계약을 깊게 설명한다. 이때 《오브젝트》·《객체지향의 사실과 오해》는 **관련성을 확인한 후** 공개 목차·해설·저자 글에서 적합한 키워드를 찾는 후보이다.
- **상황 B — Spring Bean 생명주기 설명:** `$concept-learning Spring Bean 생명주기 설명해줘` → 관련된 Spring 컨테이너·Bean 스코프·초기화/소멸 훅의 근거·공개 기술 블로그를 조사한다. **무관한 객체지향 서적을 무조건 인용하거나 같은 강의 예제를 가져오면 실패**다.
- **상황 C — Java 다형성 정리:** `$concept-learning Java 다형성 정리해줘` → **SUMMARIZE**에서 핵심 개념, 컴파일 시점 타입과 런타임 구현 선택의 차이, 사용 조건과 주의점 정도를 정확히 압축한다. **EXPLAIN과 같은 긴 Dog/Cat 예제·모든 자료/이미지 탐색·상세 심화는 요구하지 않는다.**
- **상황 D — Spring Bean 생명주기 정리:** `$concept-learning Spring Bean 생명주기 핵심만 정리해줘` → **SUMMARIZE**에서 생성·주입·초기화·사용·종료와 스코프/콜백 조건만 간결하게 정리한다.
- **상황 E — 기존 학습 자료 정리:** `$concept-learning 첨부한 강의 PDF 정리해줘` → 해당 PDF를 먼저 읽고 **실제로 확인된 내용만 압축**한다. 외부 자료로 누락 내용을 임의로 보충하지 않고 자료 미확인 영역은 명시한다.
- **모든 모드 공통 실패:** 근거 없이 출처·이미지를 발명하거나, 정리 명령만으로 Wiki·Obsidian·외부 저장을 실행하거나, 서적 후보 목록을 모든 강의에 고정 출력하면 불합격이다.

## A. Java 다형성 — 런타임 선택

학습 요청: `부모 타입 변수로 자식 객체를 가리키면 메서드가 어떻게 호출돼?`

`Animal a = new Dog(); a.sound();`에서 컴파일러는 `Animal` 타입에 `sound()` 호출이 가능한지 확인하고, 실행할 때 가리키는 객체 `Dog`의 오버라이딩된 메서드를 선택한다. 부모 타입 변수가 Dog 객체를 Animal 객체로 바꾸는 것은 아니다.

- **합격:** 참조 변수의 선언 타입과 실제 객체, 정적 호출 가능성, 동적 디스패치가 연결된다.
- **실패:** `부모 클래스의 메서드가 무조건 실행된다`, `객체가 부모로 변경된다`, 메서드 오버로딩과 오버라이딩 혼동.
- **답변 모양:** 코드 1블록과 호출 전·후 간단한 설명으로 충분하다. JVM 세부 method table은 현재 질문에 필요하지 않다.

## B. Spring 트랜잭션 — 프록시 경계

학습 요청: `같은 서비스 안에서 @Transactional 메서드를 호출하면 왜 적용이 안 될 수 있어?`

Spring의 일반적인 프록시 기반 트랜잭션에서는 외부 호출이 프록시를 지나야 인터셉터가 트랜잭션을 시작한다. 같은 인스턴스의 `this.inner()`는 프록시를 거치지 않으므로 `inner()`의 트랜잭션 속성이 새로 적용되지 않을 수 있다. 이미 외부 호출에 의해 트랜잭션이 시작됐다면 내부 메서드가 그 트랜잭션 **안에서 실행될 수 있다는 점**은 별도로 구분한다. AspectJ weaving 등 다른 구성을 모든 Spring 환경과 동일하게 단정하지 않는다.

- **합격:** 외부 호출·자기 호출을 나눠 설명하고 프록시 방식이라는 조건을 명시한다.
- **실패:** `자기 호출이면 모든 DB 작업이 트랜잭션 밖이다`라는 일반화, annotation만 붙이면 어떤 호출에서도 작동한다고 주장.

## C. JPA flush — SQL과 커밋

학습 요청: `flush()와 commit의 차이는?`

`flush`는 영속성 컨텍스트에 누적된 변경을 DB에 SQL로 동기화할 수 있지만, **트랜잭션을 확정하는 commit 자체는 아니다**. 실행된 SQL도 이후 롤백되면 트랜잭션 변경이 취소될 수 있다. 어떤 SQL이 언제 나가는지는 ID 생성 방식·설정·flush 모드·현재 영속 상태를 살펴야 한다.

- **합격:** SQL 실행, DB 트랜잭션 커밋, 1차 캐시의 개념을 분리한다.
- **실패:** `flush 즉시 데이터 영구 저장`, `save() 즉시 항상 INSERT`.

## D. Linux systemd — 실제 출력 해석

학습 요청: `systemctl is-active가 inactive이고 is-enabled는 enabled라고 나오는데?`

`inactive`는 현재 서비스가 활성 상태가 아니라는 뜻이고, `enabled`는 자동 시작을 위한 구성 상태를 가리킨다. 서로 다른 축이므로 동시에 나타날 수 있다. 실패 원인을 단정하지 않고 `systemctl status ...`와 필요한 로그를 확인할 때 무엇을 봐야 하는지 설명한다.

- **합격:** 사용자가 제공한 **실제 출력**에 근거하고 서비스 상태와 부팅 설정을 구분한다.
- **실패:** 출력이 없는데 `재시작 성공` 주장, 서비스가 현재 실행 중이라고 단정.

## E. 참고 자료·이미지

학습 요청: `Spring MVC 요청 흐름을 한국 기술 블로그 자료와 그림으로 설명해줘.`

- **합격:** 실제 공식 문서와 한국어 기술 글을 조사해 기술 버전·출처·관련 구간을 확인하고, DispatcherServlet에서 핸들러·어댑터·응답 변환까지 본문이 스스로 설명한다. 확인된 공개 이미지의 구조·시점도 본문에서 설명하고 실제 표시/권한 범위를 밝힌다.
- **실패:** 읽지 않은 블로그를 인용, 권한 미확인 이미지를 무단 복제, 링크만 나열하고 설명이 없음.
- **미확인:** 외부 도구 접속 실패는 자료 확보 실패로 기록한다. 인용을 창작하지 않는다.
