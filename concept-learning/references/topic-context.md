# 주제 맥락과 학습 방식의 경계

이 문서는 **주제 선정과 설명 방식의 책임을 분리**하기 위한 짧은 지침이다. `concept-learning`은 사용자가 이미 고른 기술 주제를 강의하는 스킬이며, 과목별 로드맵을 생성·관리하는 도구가 아니다.

## 동일한 교수법을 적용하는 두 진입점

- **기존 로드맵 안의 주제:** 사용자가 Java 로드맵을 정한 뒤 `$concept-learning 다형성1부터 진행하자`라고 말한다. 현재 채팅의 로드맵 범위와 강의 PDF가 있으면 이를 참고하여 **다형성1을 바로 설명**한다. 로드맵 재설계, 단계별 메뉴 제시, 강의 완료 기록부터 시작하지 않는다.
- **독립 개념 학습:** `$concept-learning Spring의 Bean 생명주기를 설명해줘`라고 말한다. 로드맵 유무를 물을 필요 없이 Bean 초기화/소멸과 실제 동작을 정확하게 강의한다.
- **후속 질문:** `초기화 콜백은 언제 호출돼?`처럼 물으면 직전 맥락을 이어 해당 지점만 심화한다. 현재 주제를 변경하거나 처음부터 모두 설명하지 않는다.
- **주제 없이 이어서:** `다음 주제 진행하자`인데 현재 대화에서 그 주제를 확인할 수 없으면 바로 새 커리큘럼을 만들지 않고 **무슨 주제인지 한 가지 질문**으로 확인한다.

## 유지할 것과 하지 않을 것

기존 로드맵·교재·PDF·수업 범위가 보이면 **주제의 배경과 설명에만** 활용한다. 클라이언트가 과거 대화에 접근할 수 없다면 접근했다고 말하지 않는다. 특정 주제가 명시되어 있으면 외부 진도를 조회할 필요가 없다.

이 스킬 자체는 로드맵을 설계·편집·병합하거나 학습 회차를 기록·자동 이동하지 않는다. 사용자에게 선택된 주제의 설명을 완성한 뒤 멈춘다. 강의 중 필요하면 표·코드·이미지를 활용하지만 불필요한 퀴즈나 과제를 추가하지 않는다.
