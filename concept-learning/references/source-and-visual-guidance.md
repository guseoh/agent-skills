# 한글 참고 자료·강의 이미지·도식 활용 기준

강사의 설명을 풍부하게 만드는 **자료 조사와 시각 자료 활용**에 관한 실천 규칙이다. 특정 링크 수나 이미지 수를 채우기 위한 장식, 사실을 검증하지 않은 인용은 금지한다.

## 자료 찾기와 실제 본문 반영

1. **무엇을 설명할지 먼저 결정한다.** 현재 학습 주제의 정의·실행 순서·오해하기 쉬운 조건·실무 질문 중 어느 부분을 뒷받침할 자료인지 정한다.
2. **정확성 근거:** 사용 버전의 공식 명세, 프레임워크 레퍼런스, DB/OS 공식 문서 및 원본 코드를 우선 확인한다. 공식 문서는 늘 좋은 입문 설명을 제공하는 것은 아니므로 한국어 해설로 설명을 보완한다.
3. **한글 자료 적극 조사:** 해당 개념을 구체적으로 다룬 한국 IT 기업 기술 블로그, 공식 한국어 문서, 검증된 한국어 학습 글을 찾는다. 우아한형제들·토스·카카오·네이버 등은 **관련 글이 실제 존재할 때만** 후보가 된다. 기업 이름만 보고 출처 신뢰도·현재 주제 적합도를 보장하지 않는다.
4. **실제로 읽고 분별한다.** 글의 발행/업데이트 날짜·프레임워크/DB 버전·사례의 전제·재현 여부를 확인한다. 개인 경험담은 일반적인 언어·프레임워크 계약과 구분한다.
5. **자료를 강의에 통합한다.** 소제목의 설명 속에 원문이 제시한 핵심 기법·문제 조건·대안을 재서술한다. 사용자에게 **링크를 열지 않아도 개념이 이해될 만큼** 설명하며, 출처 링크는 관련 문단 곁에 남긴다. 사후에 참고 URL만 한꺼번에 나열하는 행위는 피한다.
6. **필요한 만큼만 쓴다.** 관련 내용이 없는 한국어 기사보다 정확한 공식 문서 1개가 낫다. 검색/열람이 실패하면 확인하지 못한 자료나 URL을 발명하지 않고 검증 범위를 밝힌다.

## 이미지 우선 탐색과 도식 선택

1. 구조·메모리·상태 변화·요청/트랜잭션의 시간 흐름처럼 그림으로 이해가 쉬운 주제에서는 **실제 그림을 찾아 본문에 포함할 수 있는지** 먼저 검토한다. 이미지가 본문의 핵심 설명을 대체하지 않아야 한다.
2. **실제 공개 강의 이미지**와 **일반 한국어 기술 블로그의 자체 그림**을 구분한다. 강의 정리 블로그가 텍스트만 제공하는데 강의 원본 그림이라고 소개하지 않는다. 문서/이미지의 출처, 실제 내용, 라이선스·이용 가능 범위를 확인하고 출처를 함께 제공한다.
3. 그림에서 학습자가 보아야 할 구조·화살표·상태 변화와 무엇을 생략했는지 본문에서 해설한다. 텍스트만으로 충분한 개념에는 무의미한 그림을 끼워 넣지 않는다.
4. 적합한 원본 그림을 사용할 수 없거나 오해 가능성이 있다면 필요한 범위에서 **자체 도식**을 사용한다. 가로형과 흑백·단순 구성을 기본 선호로 두되 관계·상태·시간 표현에 맞는 배치를 우선한다. 같은 박스-화살표를 반복하거나 외관을 과도하게 꾸미지 않는다.
5. 외부 그림의 무단 복제/임베드, 출처를 알 수 없는 스크린샷, 모델이 상상한 URL은 사용하지 않는다. 그림의 이용 조건이 불명확하면 텍스트로 설명하고 출처 페이지를 링크하거나 독립 도식을 제작한다.
6. 이미지 검색·표시 기능이나 원본 접근이 불가능하면 **그림을 실제로 제시한 척하지 않는다.** 해당 환경에서 가능한 확인된 설명·정확한 링크/표/자체 도식 중 적절한 것을 선택한다.

## 코드·표·글머리표와의 균형

- 코드 전: **왜 이 코드를 보는지, 어떤 상태/전제인지** 간단히 말한다.
- 코드 후: **호출 순서·값/참조·상태/SQL 변화와 결과**를 하나의 문단으로 연결하고 필요한 구성 요소만 글머리표로 정리한다.
- 핵심 비교는 표를 사용하되, 중요한 인과관계 자체를 표만으로 생략하지 않는다.
- 소제목마다 한 줄 설명을 반복하는 레이아웃보다 자연스럽게 이어지는 문단을 우선한다. 기술별 중요도에 따라 코드·그림·자료 비중은 달라도 된다.

## 정성적 합격 예시

- Spring Bean 생명주기: 초기화/소멸 호출 흐름을 본문에서 설명하고, 실제 생성·초기화·소멸 시점을 담은 공개 그림이 적합한 경우 출처와 함께 사용한다. 공식 Spring 문서와 한국어 해설 글의 각각 다른 역할을 설명한다.
- DB MVCC: 사용 DB·격리 수준을 먼저 밝힌 상태에서 두 트랜잭션의 읽기 시점과 버전 가시성을 도식/표로 비교한다. 실제 읽지 않은 실무 장애 사례는 인용하지 않는다.
- Java 다형성: 부모 타입 참조의 호출 제약과 실제 인스턴스 메서드 선택을 코드+실행 설명으로 보여준다. 별도 그림이 추가 가치를 제공하지 않으면 코드와 문단으로 끝내도 된다.

**검증 한계:** 이 파일은 설명을 작성하는 규칙이지, 실제 검색/이미지 조회/브라우저 렌더링이 성공했다는 기록이 아니다.
