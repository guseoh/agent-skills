# CS learning visualization

CS 학습자의 이해를 돕는 **정확하고 읽기 쉬운 기술 그림**을 만든다. 기본은 정적인 SVG다. 시각화가 필요 없는 개념에는 그림을 추가하지 않는다. 그림마다 같은 박스·화살표 템플릿을 강요하지 않는다. 구조와 인과관계가 먼저 보이도록 하며, 시각적 장식과 인터랙션 자체를 목표로 삼지 않는다.

## 작업 전 확인

1. 프로젝트별 콘텐츠·디자인 규칙과 사용자의 최신 결정을 먼저 읽는다. CSForge에서는 기존 canonical 개념 문서, 예제 코드, Reader 구조 및 검증 계약이 기준이다. 사용자 이력·기존 콘텐츠 식별자를 함부로 변경하지 않는다.
2. 학습 목표를 한 문장으로 정의한다. 그림을 읽은 학습자가 설명할 관계·전후 상태·불변식과, **그림에 넣지 않을 세부사항**을 적는다.
3. 기술 의미를 공식 명세·구현 문서·재현 가능한 코드로 확인한다. 언어 보장/프레임워크 계약/런타임 구현/OS·하드웨어를 혼동하지 않는다. 특정 DB·JDK·TCP 조건에 의존하면 범위를 그림 설명에 붙인다.
4. 참고 원본이 있다면 구성 방식만 연구한다. Hello Algo의 **학습 순서에 맞춘 그림 구성**과 Learn DSA Visually의 **의존성 없는 독립 SVG/CSS 방식**을 참고하되 도형·코드·문장을 무단 복사하지 않는다. 원본 링크·라이선스를 조사하고 직접 제작한 결과와 구분한다.

## 시각화가 필요한지 먼저 판단

| 선택 | 판단 기준 | 결과 |
| --- | --- | --- |
| 없음 | 본문과 작은 코드 예시만으로 충분 | 그림을 억지로 추가하지 않음 |
| 정적 구조 | 관계·배치·대응을 한눈에 설명 | 단일 SVG 기본값 |
| 정적 상태 비교 | 두세 상태를 동시에 비교해야 이해 가능 | 나란히 놓인 패널, 독립 SVG |
| 순차 단계 | 중간 순서가 핵심이고 정적 비교가 길어짐 | 읽을 수 있는 단계별 SVG 또는 CSS 모션 |
| 조작형 | 학습자의 입력·스케줄 변경이 결과를 바꿈 | 테스트 가능한 상태 모델 + UI; React는 선택 사항 |

직접 조작할 기능이 필요하다는 실증 근거 없이는 React Flow, D3, 애니메이션 프레임워크를 추가하지 않는다. 애니메이션은 필수 상태를 숨기지 말고 정지·감속 동작 및 정적 대체를 제공한다.

## 교재형 SVG 작성 규칙

- **기하가 내용이다.** 트리는 부모·자식 위치, 배열은 인덱스, 참조는 변수와 객체의 연결, TCP는 시간·범위·ACK 의미를 공간 배치로 설명한다. 과도한 카드 중첩, 장식 아이콘, 그림자, 그라디언트, 무의미한 색상은 피한다.
- 단색/중립 회색을 기본으로 하고 선 굵기·실선/점선·위치·짧은 레이블로 상태를 구분한다. 색상만으로 정답·대기·변경을 전달하지 않는다. 라이트·다크 모두 대비를 확인한다.
- 독립적인 `.svg`와 `viewBox`를 우선한다. `role="img"`, `aria-labelledby`, `title`, `desc`를 제공하고 접근성 좋은 텍스트 레이블을 포함한다. 외부 이미지·웹폰트·스크립트·원격 요청을 SVG에 넣지 않는다.
- 데스크톱 Reader 폭에서 먼저 검증한다. 긴 텍스트·번호 잘림, 겹침, 화살표 방향, 배경색, 주변 본문 글자 크기와의 균형을 점검한다. 축소된 모바일 화면만을 위해 학습 내용을 희생하지 않는다.
- 시각화 안의 한국어는 짧고 자연스럽게 사용한다. 주요 의미와 조건은 SVG 캡션/본문에서도 설명하므로 이미지만으로 모든 설명을 반복하지 않는다.
- 정적 상태는 기본적으로 정지한 상태에서 의미를 완전히 전달해야 한다. 사용자 조작, 자동 루프, 클릭 이벤트, 배포 의존성은 선택 사항이다.
- **전후 상태를 나란히 비교할 때 유지되는 대상은 두 패널에서 같은 상대 좌표·크기·명칭으로 배치한다.** 변경되지 않은 객체를 다른 곳으로 움직이면 실제 재할당이나 이동으로 오해할 수 있다. 바뀐 참조 화살표와 새로 생성된 객체 등 **변화한 부분만** 차이를 드러낸다.
- 코드 실행 그림에는 가능하면 **호출부 + 실제 메서드 본문**을 짧게 제공한다. 코드의 실행 위치와 그래픽의 시점이 일치해야 하고, 수식·설명은 그림을 반복하지 않고 원인을 연결한다.
- 구조(Heap)에는 **선택 노드 ↔ 같은 배열 인덱스**, 관계 대상, 실제 계산식을 동기화할 수 있다. 시간순 변화(TCP)에는 전후 범위와 ACK 관계를 공간 배치로 표현한다. 세 형식을 같은 템플릿으로 강제하지 않는다.

## 생성·검수 절차

1. **사실 모델:** 값·노드·인덱스·참조·패킷/바이트 범위·트랜잭션 순서와 불변식을 표기한다. 가정과 설명에서 생략한 계층을 따로 적는다.
2. **레이아웃 선택:** 구조·상태비교·시간축 중 하나를 선택하고, 왜 그 배치가 학습 목표를 가장 명확히 하는지 설명한다.
3. **SVG 제작:** 위 요소만 담고, 고정 `width` 대신 `viewBox`로 크기를 조절한다. 필요하면 별도 SVG 파일로 상태를 나눈다.
4. **의미 검증:** 예시 값을 손으로 추적하거나 코드/프로토콜 문서와 대조한다. 시각적으로 완성돼도 사실이 틀리면 불합격이다.
5. **렌더링 검수:** 라이트/다크 및 데스크톱 두 너비에서 실제 SVG를 열어 텍스트·선·화살표·대비를 검사한다. 렌더링 미실행을 실행했다고 쓰지 않는다.
6. **사용 맥락 검수:** Reader 본문과 나란히 놓였을 때 적절한지, 중복 설명과 불필요한 상호작용이 없는지 확인한다.
7. **결과:** 원본 SVG, 학습 목표, 검증 근거, 테스트한 환경, 알려진 한계와 남은 작업을 함께 보고한다. 프로젝트 통합/DB 반영/배포·병합은 별도 승인과 절차가 필요하다.

## 세 가지 기준 사례의 합격 조건

### A. Heap — 트리와 배열의 대응

최소 힙의 부모값 <= 자식값 불변식과 완전 이진 트리의 배열 인덱스 `parent=(i-1)//2`, `left=2i+1`, `right=2i+2`를 검증한다. 트리의 0~n-1 인덱스가 아래 배열의 같은 인덱스와 정확하게 일치해야 한다. 정적 그림만으로도 구조를 설명할 수 있지만, 사용자가 확인한 CSForge 예제에서는 **노드 또는 배열 칸을 선택하면 같은 인덱스를 동기화하고 부모·자식·수식을 표시하는 최소한의 인터랙션**이 학습에 도움이 되었다. 클릭 기능 없이도 한눈에 구조를 읽을 수 있어야 한다. 텍스트만 있는 흐름도와 트리·배열을 연결하지 않은 그림은 불합격이다.

### B. Java Pass-by-Value — 참조값 복사

Java는 인자를 값으로 전달한다. 참조값이 매개변수에 복사되므로 두 변수가 **같은 객체를 가리킬 수 있지만**, 매개변수 재할당만으로 호출자 변수가 바뀌지 않는다. 메서드 실행 도중의 전후 상태와 객체 정체성을 분리한다. 참조값 복사와 객체 복사를 혼동하거나 재할당을 객체 상태 변경으로 묘사하면 불합격이다. 전후 두 패널에서 **객체 A의 상대 좌표·크기를 동일하게 유지하고**, 새로운 객체 B와 `param`의 참조 대상만 달라진 상태를 표시한다. `replace(Member param) { param = new Member(...) }`처럼 실제 메서드 본문을 함께 제시한다. 정적 상태 비교를 우선한다.

### C. TCP Sliding Window — 바이트와 누적 ACK

실제 TCP의 sequence/ACK 번호는 **세그먼트 번호가 아닌 바이트 단위**라는 점을 유지한다. 예시 데이터 길이, 다음 수신 기대 바이트, 누적 ACK의 범위, 송신 윈도우의 전후 위치를 일관되게 한다. advertised window와 congestion control의 가정(예: rwnd 400B, cwnd 충분, 손실 없음)을 명시한다. ACK 하나로 윈도우가 이동하는 정적 전후 비교가 우선이다. 송신 상태와 수신 ACK를 섞거나 ACK를 수신한 세그먼트 개수로 해석하면 불합격이다.

## CSForge 실사용 시안에서 도출한 제작 기준

[CSForge Draft PR #297](https://github.com/guseoh/csforge/pull/297)의 세 가지 독립 미리보기를 레이아웃 참고 자료로 활용한다. 사용자가 직접 확인한 것은 **Heap 교재형 화면의 시각적 방향**이며, Java/TCP의 최종 Reader 반영이나 전체 콘텐츠 적용을 승인한 것으로 간주하지 않는다.

- **Heap:** 하나의 화면에 트리와 인덱스 배열을 함께 배치한다. 선택된 원소와 부모·자식은 배경·선 굵기로 차이를 주며 계산식과 실제 값을 연결한다. 자유 드래그·줌·자동 애니메이션은 없다.
- **Java:** 호출부와 매개변수를 동일 객체에 연결한 후 재할당 시 매개변수만 새 객체로 연결한다. 객체 A는 두 패널에 걸쳐 **같은 위치**를 유지한다. 간단한 호출 코드와 메서드 본문을 그림과 함께 배치한다.
- **TCP:** 전송 전후 범위를 시간순으로 배치하고 점선 송신 윈도우, 빗금 누적 ACK, 송신·대기·전송 가능 상태를 분리한다. 세그먼트가 아닌 바이트로 계산한다.
- **자동/수동 검증 구분:** PR에서 컴포넌트 단위·브라우저 QA가 통과했다 해도 플러그인의 **별도 SVG 파일**과 실제 Reader 콘텐츠의 시각 품질까지 인증된 것은 아니다. 최종 이용 화면의 빛/어둠 테마, 대비, 좌표 정렬, 텍스트 넘침을 확인하고 검증 근거를 남긴다.

## 경계

플러그인은 **그림 제작·검토 지침**이며, 자체 렌더링 엔진·MCP 서버가 아니다. 외부 사이트의 예제를 실행하거나 콘텐츠를 자동 게시하지 않는다. CSForge의 기존 학습 데이터·프로덕션 DB·사용자 이력·릴리스 상태를 변경하지 않으며, 다른 플러그인을 무조건 호출하지 않는다. 기존 Stack Diagram은 서비스 아키텍처용으로 분리한다.
